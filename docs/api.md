# API Reference

Base URL: `http://localhost:8000/api/v1` (configurable via the frontend's
`VITE_API_BASE_URL`). Interactive docs are auto-generated by FastAPI at
`http://localhost:8000/docs`.

All request/response bodies are JSON except the upload endpoint, which
is `multipart/form-data`.

## Health

### `GET /health`

Liveness check.

**Response `200`**
```json
{ "status": "ok" }
```

## Resumes

See [docs/resume-processing.md](./resume-processing.md) for the
conceptual flow (upload → parse → review → verify) these endpoints
implement, and [docs/database.md](./database.md) for the underlying
schema.

### `POST /resumes`

Upload a resume file. `multipart/form-data` with a single field, `file`.

- Accepted extensions: `.pdf`, `.docx` (see `ALLOWED_UPLOAD_EXTENSIONS`)
- Max size: 10 MB by default (see `MAX_UPLOAD_SIZE_MB`)
- The file is validated, stored, and parsed synchronously as part of
  this request - the response already reflects the parse outcome.

**Response `201`**
```json
{
  "id": "b3f1c2b0-...",
  "original_filename": "resume.docx",
  "status": "parsed",
  "parse_error": null
}
```

`status` will be `"parsed"` if structured data was found, or
`"needs_review"` if parsing succeeded but found little/nothing (with
`parse_error` explaining why).

**Response `400`** — invalid upload (unsupported type, oversized, empty,
missing/unsafe filename, or content that doesn't match its declared
extension):
```json
{ "detail": "Unsupported file type '.txt'. Allowed types: .pdf, .docx." }
```

### `GET /resumes`

List all uploaded resumes (lightweight summaries - no nested sections).

**Response `200`**
```json
[
  {
    "id": "b3f1c2b0-...",
    "original_filename": "resume.docx",
    "status": "verified",
    "full_name": "Jane Doe",
    "created_at": "2026-01-01T12:00:00",
    "updated_at": "2026-01-01T12:05:00"
  }
]
```

### `GET /resumes/{resume_id}/profile`

Fetch the full structured profile for one resume: contact info, and
every extracted skill/experience/project/education/certification, each
with `source` and `verified` metadata.

**Response `200`**
```json
{
  "id": "b3f1c2b0-...",
  "original_filename": "resume.docx",
  "status": "parsed",
  "full_name": "Jane Doe",
  "email": "jane.doe@example.com",
  "phone": "(512) 555-1234",
  "location": "Austin, TX",
  "summary": "Experienced software engineer...",
  "parse_error": null,
  "verified_at": null,
  "created_at": "2026-01-01T12:00:00",
  "updated_at": "2026-01-01T12:00:00",
  "sections": [
    { "id": "...", "section_type": "experience", "heading": "Experience", "content": "...", "sort_order": 1 }
  ],
  "skills": [
    { "id": "...", "name": "Python", "category": null, "source": "resume", "verified": false }
  ],
  "experiences": [
    {
      "id": "...", "job_title": "Senior Software Engineer", "company": "Acme Corp",
      "location": "Austin, TX", "start_date": "Jan 2020", "end_date": null,
      "is_current": true, "description": "Built scalable APIs...",
      "source": "resume", "verified": false
    }
  ],
  "projects": [ /* ... */ ],
  "education_entries": [ /* ... */ ],
  "certifications": [ /* ... */ ]
}
```

**Response `404`** — no resume with that id.

### `PUT /resumes/{resume_id}`

Correct extracted information. Any scalar field omitted from the request
body is left unchanged. Any list field that **is** provided fully
replaces that section - submit the section's complete, corrected list
(there's no partial-item PATCH). Every item submitted this way is
recorded with `source: "user"`.

**Request body** (all fields optional)
```json
{
  "full_name": "Jane A. Doe",
  "email": "jane.a.doe@example.com",
  "phone": "555-0000",
  "location": "Austin, TX",
  "summary": "...",
  "skills": [
    { "name": "Python", "verified": true },
    { "name": "Kubernetes", "verified": true }
  ],
  "experiences": [ { "job_title": "...", "company": "...", "verified": true, "...": "..." } ],
  "projects": [ { "name": "...", "verified": true, "...": "..." } ],
  "education_entries": [ { "institution": "...", "verified": true, "...": "..." } ],
  "certifications": [ { "name": "...", "verified": true, "...": "..." } ]
}
```

**Response `200`** — the updated `ResumeProfileOut` (same shape as
`GET .../profile`).

**Response `404`** — no resume with that id.

**Response `409`** — the resume is already `verified`; corrections are
no longer accepted once verified. Upload a new resume instead.

### `POST /resumes/{resume_id}/verify`

Mark a resume's profile as verified. This is the only state transition
that makes a resume eligible for matching/tailoring in a future sprint
(enforced there via `ResumeService.assert_verified()`, not yet called by
anything in this sprint since no matching engine exists yet).

**Response `200`** — the updated `ResumeProfileOut`, with `status:
"verified"` and `verified_at` set. Calling this again on an
already-verified resume is a no-op that still returns `200`.

**Response `404`** — no resume with that id.

**Response `409`** — the resume hasn't been parsed yet (status is still
`uploaded`) and can't be verified.

## Error format

All error responses follow FastAPI's default shape:

```json
{ "detail": "Human-readable message" }
```
